Implementasi Klasifikasi & Regresi Random Forest#

Menggunakan KNIME Analytics Platform#

Nama: Fahdimas Akmal

1. Landasan Teori: Random Forest#

Dalam tugas ini, saya menerapkan algoritma Random Forest, yaitu metode ensemble learning yang membangun banyak pohon keputusan (Decision Trees) secara acak untuk mendapatkan hasil prediksi yang lebih stabil dan akurat.

Algoritma ini bekerja dengan tiga prinsip utama:

  • Bootstrapping: Mengambil sampel data secara acak dengan pengembalian untuk melatih setiap pohon individu.

  • Feature Randomness: Memilih subset fitur secara acak di setiap pembelahan (split) pohon untuk meningkatkan variasi antar pohon.

  • Aggregation (Voting/Averaging): Menggabungkan hasil dari semua pohon untuk menentukan hasil akhir (klasifikasi berdasarkan suara terbanyak, regresi berdasarkan nilai rata-rata).

2. Alur Workflow Lengkap#

Berikut adalah visualisasi rangkaian node yang saya bangun di KNIME. Workflow ini terbagi menjadi dua jalur utama setelah pembagian data: jalur atas untuk klasifikasi “Play Tennis” dan jalur bawah untuk regresi variabel “Wind”.

Tahapan Alur:

  1. Input Data: Membaca dataset melalui Excel/File Reader.

  2. Partisi: Membagi data menjadi 80% Training dan 20% Testing menggunakan Table Partitioner.

  3. Pelatihan (Learner): Data latih masuk ke node Learner untuk klasifikasi dan regresi.

  4. Prediksi: Model yang sudah dilatih memproses data uji pada node Predictor.

  5. Evaluasi: Hasil diukur menggunakan tiga jenis Scorer (Testing, OOB, dan Numeric).

3. Dokumentasi Konfigurasi Node#

A. Konfigurasi Table Partitioner#

Saya membagi dataset menggunakan port Relative Size 80%. Saya menggunakan Stratified Sampling pada kolom “Play Tennis” agar distribusi kelas “Yes” dan “No” di data training dan testing tetap seimbang sesuai proporsi aslinya.

B. Konfigurasi Random Forest Learner#

Saya menentukan target kolom “Play Tennis” dengan atribut pendukung Day, Outlook, dan Temp. Kriteria pemisahan yang digunakan adalah Gini Index untuk memastikan setiap cabang pohon memiliki tingkat kemurnian data yang tinggi.

4. Simulasi Perhitungan Manual (Gini Impurity)#

Untuk memahami logika di balik pemilihan akar pohon (root node), saya menghitung Gini Impurity pada akar pohon menggunakan data awal (14 baris).

Rumus Gini Impurity:#

\[Gini(S) = 1 - \sum_{i=1}^{n} (p_i)^2\]

Keterangan Simbol:

  • \(Gini(S)\): Nilai ketidakmurnian dataset. Nilai 0 berarti murni, sedangkan nilai mendekati 0.5 berarti data sangat beragam.

  • \(1\): Konstanta yang melambangkan total probabilitas (100%).

  • \(\sum\): Simbol Sigma yang berarti penjumlahan hasil kuadrat probabilitas untuk setiap kelas.

  • \(p_i\): Probabilitas kelas \(i\), dihitung dengan: \((\text{Jumlah sampel kelas } i) / (\text{Total seluruh sampel})\).

Langkah Perhitungan (Data Keseluruhan):#

Berdasarkan dataset: Total data = 14. Jumlah “Yes” = 9, Jumlah “No” = 5.

  1. Hitung Probabilitas (\(p\)):

    • \(p_{Yes} = 9/14 \approx 0.643\)

    • \(p_{No} = 5/14 \approx 0.357\)

  2. Masukkan ke Rumus:

    • \(Gini(S) = 1 - [(0.643)^2 + (0.357)^2]\)

    • \(Gini(S) = 1 - [0.413 + 0.127]\)

    • \(Gini(S) = 1 - 0.540 = \mathbf{0.460}\)

5. Hasil Evaluasi Model#

A. Scorer Out-of-Bag (OOB)#

Scorer ini menunjukkan estimasi akurasi internal selama proses pelatihan.

  • Akurasi OOB: 36.364%. Rendahnya akurasi OOB ini dikarenakan jumlah sampel yang sedikit (14 baris), sehingga variasi pohon belum cukup kuat untuk generalisasi internal.

B. Scorer Klasifikasi (Data Testing 20%)#

Mengevaluasi performa nyata model pada data yang belum pernah dilihat.

  • Correct Classified: 2 sampel.

  • Accuracy: 66.667%.

C. Numeric Scorer & Visualisasi Regresi#

Digunakan untuk memprediksi nilai numerik “Wind”. Grafik Line Plot di bawah menunjukkan fluktuasi antara nilai Actual (biru) dan Prediction (ungu/merah).

Visualisasi Plot

6. Analisis Hasil Akhir#

Dalam tugas ini, saya menemukan bahwa algoritma Random Forest sangat tangguh karena mampu menangani klasifikasi dan regresi dalam satu alur kerja. Meskipun akurasi testing mencapai 66.67%, akurasi OOB yang rendah memberikan catatan penting bahwa model ini akan bekerja jauh lebih optimal jika diberikan dataset yang lebih besar. Penggunaan Normalisasi terbukti krusial untuk menyelaraskan fitur cuaca agar tidak ada atribut yang mendominasi perhitungan Gini secara tidak adil.
